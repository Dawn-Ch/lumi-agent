# Lumi Agent 命名与兼容性记录

> 状态：Accepted
> 版本：v0.1
> 日期：2026-08-15
> 范围：为现有 minimal SWE Agent 增加项目称呼与兼容入口；不改变架构、运行逻辑、协议和学习路线
> 关联：`README.md`、`main.py`、`agent/agent.py`、`agent/core/prompt.py`、`pyproject.toml`
> 证据：`compileall`、Python import/identity 检查、CLI `--help`、`pyproject.toml` scripts 检查
> 决策：采用 Lumi Agent 作为用户可见名称；保留 minimal SWE Agent 作为技术定位与兼容标识

---

## 1. 决策背景

随着项目持续迭代，需要一个稳定、简短的称呼，便于在设计讨论、文档、命令行界面和后续演示中指代同一个 Agent。

项目从 v0.1 起采用 **Lumi Agent** 作为称呼。此次变化是命名决策，不是架构升级，也不意味着项目从 minimal SWE Agent 转向另一类产品。

## 2. 命名边界

| 层面 | 决策 | 原因 |
|---|---|---|
| 用户可见名称 | Lumi Agent | 以后讨论、界面与演示统一称呼 |
| 技术定位 | minimal SWE Agent | 保持学习目标和最小实现本质 |
| GitHub 仓库 | `lumi-agent` | 与项目称呼一致；旧地址由 GitHub 重定向 |
| Python distribution | `minimal-swe-agent` | 不制造不必要的安装迁移 |
| 原有 Python API | `SWEAgent` 保留 | 兼容已有代码 |
| 新 Python API | `LumiAgent`，作为 `SWEAgent` 的别名 | 提供符合项目称呼的入口，不复制实现 |
| CLI | 新增 `lumi-agent`，保留 `swe-agent` | 新名称可用，旧命令不失效 |
| System prompt | 使用 Lumi Agent 自我称呼 | 保持模型、CLI 和文档称呼一致 |

核心不变量：

```text
Lumi Agent = 这个项目的名字
minimal SWE Agent = 这个项目的技术本质
```

## 3. 实现原则

1. 不重命名核心类并进行破坏性迁移，而是增加兼容别名；
2. 不重写历史设计文档中的原始措辞，历史记录应保留当时语境；
3. Living Document、README 和后续新文档统一使用“Lumi Agent”；
4. 首次出现时写作“Lumi Agent（minimal SWE Agent）”，后文可简称 Lumi Agent；
5. 不因品牌命名改变版本路线、Harness 学习阶段或模块职责。

## 4. 验收标准

- `from agent import LumiAgent, SWEAgent` 可用，且两者指向同一实现；
- `python main.py --help` 显示 Lumi Agent；
- 安装后 `lumi-agent` 与 `swe-agent` 指向同一入口；
- README 清楚解释名称与技术定位的关系；
- 核心 loop、tools、policy 与 parser 无行为改动；静态编译和入口冒烟检查通过。
